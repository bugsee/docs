`@bugsee/hapi` adds a request context, an `http.server` transaction and error reporting to a hapi server on Node.js. Read the [backend overview](/sdk/javascript/backend/overview) first for how context and trace correlation work.

You need an app token. Create a JavaScript application in Bugsee and choose **hapi** as its target; see [Create your app](/sdk/javascript/installation#create-your-app).

The adapter declares no peer dependency. It only relies on the shape of your `@hapi/hapi` server.

## Set up

Call `launch()` at the top of your server entry, then pass the server to `setupHapi` before `server.start()`:

```ts title="server.ts"
import { launch, setupHapi } from '@bugsee/hapi';
import Hapi from '@hapi/hapi';

launch('<your_app_token>');

const server = Hapi.server({ port: 3000 });
setupHapi(server);

// ... your routes ...

server.start().catch((error) => {
  console.error(error);
  process.exit(1);
});
```

## What it does

`setupHapi` registers two request extensions. They are added next to yours and never replace them.

| Extension | What it does |
| --- | --- |
| `onRequest` | Opens a request context, continues an inbound `traceparent` and starts an `http.server` transaction. |
| `onPreResponse` | Reports a Boom error and finishes the transaction. The response is not altered. |

By default server errors (5xx) are reported and client errors (4xx) are skipped. A client disconnect finishes the transaction as cancelled.

## Options

Pass options as the second argument of `setupHapi`.

| Option | Type | Default | Description |
| --- | --- | --- | --- |
| `user` | `(req) => string \| undefined` | off | The end-user identity for reports raised during the request. |
| `shouldReport` | `(error) => boolean` | 5xx or no status | Decides whether a thrown error is reported. |
| `onError` | `(error) => void` | none | Receives a failure of the adapter itself. It never reaches the request. |

`req` is a structural view of the hapi request: `method`, `path`, `route`, `headers` and `response`.

## Launch options

The adapter does not change the launch options. These are the ones that matter most on a server:

| Option | Default | Description |
| --- | --- | --- |
| `instrumentIncomingRequests` | `true` | Automatic per-request context and `http.server` transaction. See the [backend overview](/sdk/javascript/backend/overview#incoming-request-instrumentation). |
| `captureLocalVariables` | `false` | Attach local variables to the stack frames of a reported error. See [Diagnostics](/sdk/javascript/issue-detection/diagnostics). |
| `captureSourceContext` | `false` | Attach the source lines around each stack frame. See [Diagnostics](/sdk/javascript/issue-detection/diagnostics). |
| `detectHangs` | `true` | Report event-loop hangs. See [Hangs](/sdk/javascript/issue-detection/hangs). |
| `profiling` | `false` | Attach a rolling CPU profile to reports. See [Diagnostics](/sdk/javascript/issue-detection/diagnostics). |

`@bugsee/hapi` installs `@bugsee/bugsee` for you and re-exports everything from its Node entry, so `launch` and the SDK types come from this one package. You do not install or import `@bugsee/bugsee` separately. On Bun, see [Running on Bun](/sdk/javascript/backend/overview#running-on-bun).
