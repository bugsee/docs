`@bugsee/nestjs` adds a request context, an `http.server` transaction and error reporting to a NestJS app on the Express or Fastify platform. Read the [backend overview](/sdk/javascript/backend/overview) first for how context and trace correlation work.

You need an app token. Create a JavaScript application in Bugsee and choose **NestJS** as its target; see [Create your app](/sdk/javascript/installation#create-your-app).

## Set up

Call `launch()` at the top of your server entry, then pass the Nest application to `setupNest`:

```ts title="main.ts"
import { launch } from '@bugsee/bugsee';
import { setupNest } from '@bugsee/nestjs';
import { NestFactory } from '@nestjs/core';
import { AppModule } from './app.module';

launch('<your_app_token>');

const app = await NestFactory.create(AppModule);
setupNest(app);
await app.listen(3000);
```

## What it does

`setupNest` installs two things:

- A **context middleware** that opens a request context for each request.
- By default, a **global interceptor** that starts an `http.server` transaction, continues an inbound `traceparent`, and reports a thrown error before re-throwing it untouched. Nest's own exception filters still format the response.

A Nest `HttpException` is deliberate control flow and is not reported, whatever its status. Any other thrown error is reported.

## Choose where errors are caught

The `errorCapture` option picks the seam that catches errors.

| `errorCapture` | Catches | Notes |
| --- | --- | --- |
| `'interceptor'` (default) | Route handlers, services and pipes | Reports and re-throws. Never conflicts with your own filter. Does not see errors thrown in guards. |
| `'filter'` | Also guards | Installs a global `ExceptionFilter`. Being a catch-all, it can collide with your own global filter. |
| `'both'` | Everything above | Interceptor and filter together. An error is reported once. |

```ts
setupNest(app, { errorCapture: 'both' });
```

If you already have a global exception filter, keep the default or decorate your filter's `catch` method with `BugseeExceptionCaptured` instead of using `'filter'` or `'both'`:

```ts
import { BugseeExceptionCaptured } from '@bugsee/nestjs';

@Catch()
export class MyFilter extends BaseExceptionFilter {
  @BugseeExceptionCaptured()
  catch(exception: unknown, host: ArgumentsHost) {
    // your handling
  }
}
```

## Options

Pass options as the second argument of `setupNest`.

| Option | Type | Default | Description |
| --- | --- | --- | --- |
| `errorCapture` | `'interceptor' \| 'filter' \| 'both'` | `'interceptor'` | Where errors are caught. See above. |
| `user` | `(req) => string \| undefined` | off | The end-user identity for reports raised during the request. |
| `shouldReport` | `(error) => boolean` | skips `HttpException` | Decides whether a thrown error is reported. |
| `onError` | `(error) => void` | none | Receives a failure of the adapter itself. It never reaches the request. |

`req` is a structural view of the request of your Nest platform (Express or Fastify): `method`, `url`, `originalUrl`, `route`, `routeOptions` and `headers`.

## Launch options

The adapter does not change the launch options. These are the ones that matter most on a server:

| Option | Default | Description |
| --- | --- | --- |
| `instrumentIncomingRequests` | `true` | Automatic per-request context and `http.server` transaction. See the [backend overview](/sdk/javascript/backend/overview#incoming-request-instrumentation). |
| `captureLocalVariables` | `false` | Attach local variables to the stack frames of a reported error. See [Diagnostics](/sdk/javascript/issue-detection/diagnostics). |
| `captureSourceContext` | `false` | Attach the source lines around each stack frame. See [Diagnostics](/sdk/javascript/issue-detection/diagnostics). |
| `detectHangs` | `true` | Report event-loop hangs. See [Hangs](/sdk/javascript/issue-detection/hangs). |
| `profiling` | `false` | Attach a rolling CPU profile to reports. See [Diagnostics](/sdk/javascript/issue-detection/diagnostics). |

`@bugsee/nestjs` also re-exports everything from the Node entry of `@bugsee/bugsee`.
