`@bugsee/elysia` adds a request context, error reporting and, where the performance extension is present (Node.js, not `@bugsee/bun`), an `http.server` transaction to an Elysia app. It runs on Bun, and on Node.js through the app's fetch handler. Read the [backend overview](/sdk/javascript/backend/overview) first for how context and trace correlation work.

You need an app token. Create a JavaScript application in Bugsee and choose **Elysia** as its target; see [Create your app](/sdk/javascript/installation#create-your-app).

On Bun, also install `@bugsee/bun` and import `launch` from it, as described in [Running on Bun](/sdk/javascript/backend/overview#running-on-bun). In that setup the request context and error reporting work, but there is no `http.server` transaction.

The adapter declares no peer dependency. It only relies on the shape of your Elysia app. On Node.js it needs Node.js 18 or newer.

## Set up

Call `launch()` at the top of your server entry, then pass the app to `setupElysia`:

```ts title="server.ts"
import { launch, setupElysia } from '@bugsee/elysia';
import { Elysia } from 'elysia';

launch('<your_app_token>');

const app = new Elysia();
setupElysia(app);

// ... your routes ...
```

Hooks are scoped to the Elysia instance they are added to, so register `setupElysia` on the instance that owns your routes.

If your Elysia app type does not unify with the adapter's structural type, cast it:

```ts
import { type ElysiaAppLike, setupElysia } from '@bugsee/elysia';

setupElysia(app as unknown as ElysiaAppLike);
```

## Node.js and Bun

On Bun, the full Elysia server works.

On Node.js, Elysia's `.listen` is not supported: the adapter is tested only through the app's fetch handler, `app.fetch`, so use that. (Elysia's separate Node adapter is not covered by this SDK's tests.)

## What it does

Elysia hooks are additive, so `setupElysia` adds three without replacing yours:

| Hook | What it does |
| --- | --- |
| `onRequest` | Opens a request context, continues an inbound `traceparent` and starts an `http.server` transaction. |
| `onError` | Reports server errors, meaning a plain throw or a 5xx status. Framework control flow such as `NOT_FOUND` and `VALIDATION` is skipped. |
| `mapResponse` | Finishes the transaction without altering the response. |

## Options

Pass options as the second argument of `setupElysia`.

| Option | Type | Default | Description |
| --- | --- | --- | --- |
| `user` | `(c) => string \| undefined` | off | The end-user identity for reports raised during the request. |
| `shouldReport` | `(error) => boolean` | server errors only | Decides whether a thrown error is reported. |
| `onError` | `(error) => void` | none | Receives a failure of the adapter itself. It never reaches the request. |

`c` is a structural view of the Elysia context: `request`, `set` and `route`.

## Launch options

The adapter does not change the launch options. These are the ones that matter most on a server:

| Option | Default | Description |
| --- | --- | --- |
| `instrumentIncomingRequests` | `true` | Automatic per-request context and `http.server` transaction. See the [backend overview](/sdk/javascript/backend/overview#incoming-request-instrumentation). |
| `captureLocalVariables` | `false` | Attach local variables to the stack frames of a reported error. Always off on Bun. See [Diagnostics](/sdk/javascript/issue-detection/diagnostics). |
| `captureSourceContext` | `false` | Attach the source lines around each stack frame. See [Diagnostics](/sdk/javascript/issue-detection/diagnostics). |
| `detectHangs` | `true` | Report event-loop hangs. See [Hangs](/sdk/javascript/issue-detection/hangs). |
| `profiling` | `false` | Attach a rolling CPU profile to reports. See [Diagnostics](/sdk/javascript/issue-detection/diagnostics). |

`@bugsee/elysia` installs `@bugsee/bugsee` for you and re-exports everything from its Node entry, so `launch` and the SDK types come from this one package. You do not install or import `@bugsee/bugsee` separately. On Bun, use `@bugsee/bun` for `launch()` and note that it has no `http.server` transaction; see [Running on Bun](/sdk/javascript/backend/overview#running-on-bun).
