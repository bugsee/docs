`@bugsee/hono` adds a request context, an `http.server` transaction and error reporting to a Hono app on Node.js. Read the [backend overview](/sdk/javascript/backend/overview) first for how context and trace correlation work.

For Hono on an edge runtime, use the edge platform packages instead: [Cloudflare](/sdk/javascript/platforms/cloudflare) or [Vercel Edge](/sdk/javascript/platforms/vercel-edge).

The adapter declares no peer dependency. It only relies on the shape of your Hono app.

## Set up

Call `launch()` at the top of your server entry, then pass the app to `setupHono` before you register routes:

```ts title="server.ts"
import { launch } from '@bugsee/bugsee';
import { setupHono } from '@bugsee/hono';
import { Hono } from 'hono';

launch('<your_app_token>');

const app = new Hono();
setupHono(app);

// ... your routes ...
```

## What it does

`setupHono` registers one middleware. It opens a request context, continues an inbound `traceparent`, starts an `http.server` transaction named after the route, and, after `next()`, reports a handled error that Hono stored in `c.error`. Your `app.onError` handler is not touched.

A Hono `HTTPException` is deliberate control flow and is not reported. Any other error is reported.

## Options

Pass options as the second argument of `setupHono`.

| Option | Type | Default | Description |
| --- | --- | --- | --- |
| `user` | `(c) => string \| undefined` | off | The end-user identity for reports raised during the request. |
| `shouldReport` | `(error) => boolean` | skips `HTTPException` | Decides whether a thrown error is reported. |
| `onError` | `(error) => void` | none | Receives a failure of the adapter itself. It never reaches the request. |

`c` is a structural view of the Hono context: `c.req`, `c.res` and `c.error`.

## Launch options

The adapter does not change the launch options. These are the ones that matter most on a server:

| Option | Default | Description |
| --- | --- | --- |
| `instrumentIncomingRequests` | `true` | Automatic per-request context and `http.server` transaction. See the [backend overview](/sdk/javascript/backend/overview#incoming-request-instrumentation). |
| `captureLocalVariables` | `false` | Attach local variables to the stack frames of a reported error. See [Diagnostics](/sdk/javascript/issue-detection/diagnostics). |
| `captureSourceContext` | `false` | Attach the source lines around each stack frame. See [Diagnostics](/sdk/javascript/issue-detection/diagnostics). |
| `detectHangs` | `true` | Report event-loop hangs. See [Hangs](/sdk/javascript/issue-detection/hangs). |
| `profiling` | `false` | Attach a rolling CPU profile to reports. See [Diagnostics](/sdk/javascript/issue-detection/diagnostics). |

`@bugsee/hono` also re-exports everything from the Node entry of `@bugsee/bugsee`.
