You configure the SDK with a `BugseeOptions` object passed to `Bugsee.launch`. One set of options configures both platforms: there are no separate Android and iOS option classes.

```dart
import 'package:bugsee_flutter/bugsee_flutter.dart';

await Bugsee.launch(
  'YOUR_APP_TOKEN',
  options: const BugseeOptions(
    configDuration: 120,
    captureLogsLevel: LogLevel.info,
    configWifiOnlyUpload: true,
    detectHang: true,
  ),
);
```

## How options work

`BugseeOptions` has a typed, documented field for every option the two native SDKs register, except the options of the leak module and most deprecated ones (`captureLogsOsLog` keeps its field, but the SDK accepts it and ignores it): 100 fields at the pinned SDK versions (Android 7.6.0, iOS 7.1.0). A field is named after its key: `capture.video.frame-rate` is `captureVideoFrameRate`. The fields are generated from the option manifests the two SDKs publish, so they cannot drift from the SDKs.

- **A field you leave out keeps the SDK's own default.** Several defaults differ between Android and iOS; each field's documentation says which.
- **One configuration for both platforms.** An option that exists on one platform only (the video mode is Android's, the AVPlayer capture is iOS's) is ignored on the other, with a warning printed in debug builds. The same holds for an enum constant that one platform lacks (`FrameRate.raw` on iOS).
- **Stricter than the SDKs.** Both native SDKs silently drop an unknown key or a value of the wrong type. Here, an unknown key in `BugseeOptions.custom`, a hidden key, a value of the wrong type or a bad `endpoint` is an `ArgumentError` before anything reaches the SDK. `Bugsee.launch` surfaces it through its `Future`.
- **Keys are the SDK's.** Every option is keyed `com.bugsee.option.*`, the same keys on both platforms. The key of each field is in its documentation comment.

### Options without a field

`BugseeOptions.custom` is a map from full key to value, for options this version has no field for: the options of Bugsee modules this package does not bundle (the leak module) and the deprecated ones. A key that has a typed field is an `ArgumentError` when you also put it in `custom` ("set it in one place"). An option of a module the package does not bundle is sent, but the SDK ignores it unless your app adds that module, and a warning says so in debug builds.

```dart
const BugseeOptions(
  custom: {'com.bugsee.option.<key>': true},   // a registered key without a typed field
);
```

Enum options in `custom` take the SDK's internal value (an `int`) or a constant name. Use a typed field when there is one.

## Enums

Enum options carry the SDK's internal value, never a Dart ordinal, so they read back from the SDK as integers.

| Enum | Constants (value) | Platform |
| --- | --- | --- |
| `LogLevel` | `error` (1), `warning` (2), `info` (3), `debug` (4), `verbose` (5) | both |
| `FrameRate` | `low` (1), `medium` (2), `high` (3), `raw` (4, Android only) | both |
| `VideoQuality` | `defaultQuality` (0), `medium` (1), `high` (2) | both |
| `VideoMode` | `none` (0), `v1` (1), `v2` (2), `fullscreen` (20), `directBuffers` (21) | Android |
| `ReportSeverity` | `veryLow` (1), `medium` (2), `high` (3), `critical` (4), `blocker` (5) | both |
| `CrashHandlerType` | `bsd` (1), `mach` (2), `machAndBsd` (3) | iOS |
| `DataEncryptionMode` | `none` (0), `onDevice` (1), `endToEnd` (2) | iOS |
| `BugseeStyle` | `light` (0), `dusk` (1), `basedOnStatusBar` (2), `system` (3) | iOS |

`ReportSeverity.low` is an alias of `veryLow`: value 1 is `VeryLow` on Android and `Low` on iOS.

`captureCrashSignals` is an `int` bit set: `ABRT` 1, `SEGV` 2, `BUS` 4, `ILL` 8, `FPE` 16, `TRAP` 32 (63 is all six, `0` turns the selectable signals off). The package exports no constants for it: pass the numbers. The default, `128`, is a sentinel and not a mask: on its own it lets the SDK choose, which today is every signal. To leave out `SEGV` and `BUS`, pass `57`. On Android the value is read once, when the native crash handler is first armed in the process.

## Endpoint

`endpoint` is for an on-premises installation or a test server. Give the base URL, for example `https://bugsee.example.com`. A trailing slash and a `/v2` segment are removed, because both SDKs append the API version themselves. It must be an absolute `http` or `https` URL without a query or fragment; anything else is an `ArgumentError`. The endpoint is not one of the SDKs' public options, so it is not listed in uploaded reports and is not reachable through `custom`.

## Reading the options back

```dart
final inEffect = await Bugsee.getLaunchOptions();
final supplied = await Bugsee.getHostLaunchOptions();
```

| Method | Returns |
| --- | --- |
| `getLaunchOptions()` | The options in effect: what your app supplied, merged over the SDK's defaults. Before the first launch these are the SDK's defaults. The same on both platforms. |
| `getHostLaunchOptions()` | The options your app supplied to the last launch, without the defaults; empty before the first launch. Replaced, not merged, by the next launch. |

Both are keyed by `com.bugsee.option.*`. Enums come back as the SDK's internal integer, and floats as `double` with the precision of a 32-bit float. Internal options (`$$ENDPOINT`, `$$WRAPPER`, `$$DEBUG`) are never included.

`getHostLaunchOptions()` differs between the platforms and is not normalised: Android reports every recognised option you passed, iOS only those whose value differs from the iOS default. On iOS, an option absent from it does not mean you did not set it. Use `getLaunchOptions()` for what is in effect.

## Options and the launch result

Options apply only when the launch happens. When `Bugsee.launch` returns `alreadyRunning` (a second launch, or Android auto-init), your options were **not applied**; see [Installation](/sdk/flutter/installation#launching-twice-and-auto-init). To change options, `await Bugsee.stop()` and launch again.
