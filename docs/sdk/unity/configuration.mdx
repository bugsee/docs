:::warning[Beta]
This page documents Bugsee Unity SDK **7.x**, which is in beta and can change between betas. The stable release is **6.x**: see the [6.x documentation](/sdk/unity/v6/installation). Upgrading? See [Migrating from 6.x to 7.x](/sdk/unity/migration).
:::

You configure the SDK with launch options, the second argument of `Bugsee.Launch`. The options are the same `com.bugsee.option.*` keys the native [Android](/sdk/android/configuration) and [iOS](/sdk/ios/configuration) SDKs read. This page lists the options the package documents, with their type, default and key. The typed properties are also in the API reference and in IntelliSense.

:::warning[Defaults changed in 7.x]
Shake-to-report is off on both platforms, and the notification-bar trigger is off on Android. In 6.x, shake was on for Android and off for iOS, and the Android notification-bar trigger was on. To keep the 6.x Android behavior, set `ReportingTriggerByShake = true` and `ReportingTriggerByNotification = true` on `AndroidLaunchOptions`. Set `ReportingTriggerByShake = true` on iOS only if you want a shake trigger there.
:::

## How launch options work

`Bugsee.Launch(string appToken, Dictionary<string, object> options = null)` takes one options argument. You build it in one of three ways, and each converts to the dictionary implicitly:

| Type | Use it for |
| --- | --- |
| `AndroidLaunchOptions` | Typed properties for Android: the shared options plus the Android-only ones. |
| `IOSLaunchOptions` | Typed properties for iOS: the shared options plus the iOS-only ones. |
| `OptionsBuilder` | A fluent builder over raw keys, for shared code or keys that have no property. |

All three live in the `Bugsee.Contracts.Options` namespace.

- **Unset options keep the SDK default.** The typed properties are write-only. An option you do not set is not sent, and the native SDK applies its own default.
- **A typed property the other platform does not know is dropped.** Setting an Android-only property on an iOS launch has no effect, and the reverse. The package removes a fixed list of keys before the native SDK sees them. A key outside that list, set with `SetCustomOption`, reaches the native SDK as is.
- **`SetCustomOption(key, value)`** sets any key on a typed options object. `Clear()` removes everything you set. `ToDictionary()` returns the current map.
- **`Options` holds the key constants**, for example `Options.CaptureNetwork`. Each key is `com.bugsee.option.` plus the suffix shown in the tables below.

:::note[Name clash]
The package namespace and its static class are both named `Bugsee`. In code outside the `Bugsee` namespace, `Bugsee.Launch(...)` does not compile, because `Bugsee` resolves to the namespace. Add `using BugseeSdk = Bugsee.Bugsee;` and call `BugseeSdk.Launch(...)`, or write `Bugsee.Bugsee.Launch(...)`. The examples on this site use the alias.
:::

```csharp
using Bugsee.Contracts.Options;
using BugseeSdk = Bugsee.Bugsee;

public static class BugseeSetup
{
    public static void Start()
    {
#if UNITY_ANDROID
        var options = new AndroidLaunchOptions
        {
            ReportingTriggerByShake = true,
            ReportingTriggerByNotification = true,
            DetectAndReportHang = true,
            CaptureVideoMode = VideoMode.V2,
        };
        BugseeSdk.Launch("<your Android app token>", options);
#elif UNITY_IOS
        var options = new IOSLaunchOptions
        {
            ReportingTriggerByShake = true,
            DetectAndReportHang = true,
            CrashHandlerType = CrashHandlerType.MachAndBSD,
        };
        BugseeSdk.Launch("<your iOS app token>", options);
#endif
    }
}
```

The `OptionsBuilder` form works on both platforms from one code path. Its `Set` overloads take a key and a `bool`, `int`, `float`, `string` or `object`, and it has helpers for enum options (`SetVideoMode`, `SetVideoQuality`, `SetFrameRate`, `SetLogLevel`, `SetDefaultCrashPriority`, `SetDefaultErrorPriority`, `SetDefaultBugPriority`, `SetCrashHandlerType`, `SetCrashSignals`, `SetReportingUIStyle`) and for common switches (`Duration`, `CaptureVideo`, `CaptureNetwork`, `CaptureLogs`, `DetectAndReportCrash`, `CaptureManagedExceptions`, `CaptureUnobservedTaskExceptions`, `DetectAndReportHang`, `DetectAndReportExitNotResponding`, `DetectAndReportExitLowMemory`).

```csharp
using Bugsee.Contracts.Options;
using BugseeSdk = Bugsee.Bugsee;

public static class BugseeBuilderSetup
{
    public static void Start(string appToken)
    {
        var builder = new OptionsBuilder()
            .CaptureNetwork(false)
            .SetLogLevel(LogLevel.Warning)
            .Set(Options.ReportingTriggerByShake, true);

        BugseeSdk.Launch(appToken, builder);
    }
}
```

Read what the SDK runs with after launch: `Bugsee.GetLaunchOptions()` returns the effective options (the defaults with yours merged over them), and `Bugsee.GetHostLaunchOptions()` returns only the options your app passed. `GetLaunchOptions()` is `null` while the SDK is not launched. The keys are the native SDK's own and differ between Android and iOS. On iOS an option you set to its default value can be missing from `GetHostLaunchOptions()`, because the iOS SDK drops host options equal to their default.

A [`Relaunch`](/sdk/unity/lifecycle) replaces the whole option set rather than merging into it. Pass the full set again.

## Shared options

Every property below is available on both `AndroidLaunchOptions` and `IOSLaunchOptions`. The Platform column says where the native SDK reads it.

Defaults come from the option manifests of the pinned native SDKs (Android SDK 7.6.0, iOS SDK 7.1.0), except the three Unity-specific options, which the package defines. For what each option does in depth, see the native configuration pages: [Android](/sdk/android/configuration) and [iOS](/sdk/ios/configuration).

## CrashSignals

`CrashSignals` is a `[Flags]` enum that selects the fatal signals the native crash reporter intercepts. It is a shared option: it reaches both platforms, and on Android it is read by the `bugsee-android-ndk` module.

| Value | Bit | Meaning |
| --- | --- | --- |
| `None` | `0` | No signal. |
| `Abrt` | `1` | `SIGABRT`: `abort()`, failed assertions, uncaught exceptions. |
| `Segv` | `2` | `SIGSEGV`: invalid memory access. |
| `Bus` | `4` | `SIGBUS`: misaligned or otherwise invalid memory access. |
| `Ill` | `8` | `SIGILL`: illegal instruction. |
| `Fpe` | `16` | `SIGFPE`: arithmetic exception. |
| `Trap` | `32` | `SIGTRAP`: breakpoint or trap instruction, including Swift runtime traps. |
| `All` | `63` | Every signal above. |
| `Default` | `128` | The SDK chooses: every signal. This is the default. |

Keep the default. A real fault, such as a bad native pointer, ends the process with `SIGSEGV`, and with `Segv` and `Bus` left out that crash is not reported. Unity's IL2CPP raises a managed `NullReferenceException` from an explicit null check, not from a signal, so managed null references do not depend on these signals.

How the two platforms read a value:

- `Default` is honored only on its own. Combined with other bits, the value is used as given and the `Default` bit means nothing.
- On Android, a nonzero value other than `Default` that selects none of the six signals (for example `64`) is taken as every signal. Bits above `Trap` are masked off first, so a nonzero value left with no signal also becomes every signal. `0` (`None`) stays no signal.
- On iOS, any other value is used as given. Leaving out `Abrt` also stops uncaught Objective-C exceptions, which end in `abort()`, from being reported.

A mask meant for iOS, such as `CrashSignals.None`, also narrows or switches off native signal capture on Android when the NDK module is present. Set it per platform, or leave it out of the Android options to keep every signal.

| `IssueSeverity` | `VeryLow` (1), `Medium` (2), `High` (3), `Critical` (4), `Blocker` (5) |
| `CrashHandlerType` (iOS) | `BSD` (1), `Mach` (2), `MachAndBSD` (3, default) |
| `ReportingUIStyle` (iOS) | `Light` (0), `Dusk` (1), `BasedOnStatusBar` (2), `System` (3, default) |

`CrashHandlerType.BSD` installs BSD signal handlers. `Mach` installs a Mach exception handler plus a BSD handler for `SIGABRT`, so signals raised by software (`raise()`, `kill()`) are not reported. `MachAndBSD` reports both.
