:::warning[Beta]
This page documents Bugsee Unity SDK **7.x**, which is in beta and can change between betas. The stable release is **6.x**: see the [6.x documentation](/sdk/unity/v6/installation).
:::

:::note
This guide compares Bugsee Unity SDK 6.0.x (the `.unitypackage`, namespace `BugseePlugin`) with Bugsee Unity SDK 7.0.0-beta.1. If you are setting up a new project, start from [Installation](/sdk/unity/installation) instead.
:::

:::note[TL;DR]
7.x is a new package with a new C# API, not an upgrade in place. You install it from a git tag instead of importing a `.unitypackage`, and you delete the 6.x files. The static class is still named `Bugsee`, but it lives in the namespace `Bugsee` (it was `BugseePlugin`), so in your code you alias it: `using BugseeSdk = Bugsee.Bugsee;`. You launch with one call and no scene object: there is no `BugseeLauncher` component. Option names, enums, attachments, lifecycle events and appearance change, and several defaults change. Shake-to-report and the Android notification-bar trigger are off by default. Expect code changes in every file that touches Bugsee.
:::

## Before you start

- [ ] Commit or back up your project. The migration deletes the 6.x plugin folders and edits every file that calls Bugsee.
- [ ] Read the Beta banner above. 7.0.0-beta.1 can change between betas, and 6.x stays the stable release.
- [ ] Install 7.x from the pinned git tag with the Unity Package Manager, as described in [Installation](/sdk/unity/installation). Do not install without the `#v7.0.0-beta.1` part.

## 1. Installation and requirements

### 1.1 Replace the plugin

| | 6.x | 7.x |
| --- | --- | --- |
| Distribution | `Bugsee.unitypackage`, imported into `Assets` | Unity Package Manager package `com.bugsee.unity`, from a git tag |
| Where the files go | Three folders in `Assets`: `Assets/Plugins/Bugsee` (the scripts), `Assets/Plugins/iOS/Bugsee` (`Bugsee.a`, the headers, `BugseePlugin.m` and `BugseeAgent`) and `Assets/Plugins/Android/Bugsee-Unity.aar` | `Packages/`, read-only. The package bundles no native binaries. |
| Native SDKs | Bundled in the plugin folder | Added at build time: the Bugsee Android SDK through Gradle, the Bugsee iOS SDK through Swift Package Manager |
| Launch | A `BugseeLauncher` component on an object in your first scene, or a call you make yourself | One call, `Launch`, from any script |
| Namespace and class | `BugseePlugin`, class `Bugsee` (a `MonoBehaviour`) | Namespace `Bugsee`, static class `Bugsee` |

Do these steps in order:

1. Delete `Assets/Plugins/Bugsee` (the 6.x scripts), `Assets/Plugins/iOS/Bugsee` (the iOS library, headers and `BugseePlugin.m`) and `Assets/Plugins/Android/Bugsee-Unity.aar`. If the old AAR stays, it sits next to the Bugsee Android SDK that 7.x adds through Maven.
2. Remove the `BugseeLauncher` component from your scene, and the object you created for it, if it has no other use.
3. Remove `gameObject.AddComponent<Bugsee>()` from any code that did a manual launch. In 6.x the `Bugsee` class was a component that had to be on a scene object, and the launcher gave that object the name `bgs_gameObject`. In 7.x `Bugsee` is a static class, so `AddComponent<Bugsee>()` does not compile, and nothing in your scene is required. The package creates its own helper object, `Bugsee.MainThreadDispatcher`, before the first scene loads.
4. Remove the `BugseeEventsListener` component from your main camera if you added it for GPU information. The 7.x package has no such component.
5. If you wrote your own `partial class BugseeLauncher` (in namespace `BugseePlugin`) that set `AndroidOptionsHandler` and `IosOptionsHandler`, delete that file and move its options into your own launch code (see section 2).
6. Add the package from `https://github.com/bugsee/bugsee-unity.git#v7.0.0-beta.1`. See [Installation](/sdk/unity/installation).

The package needs no scoped registry and no custom Gradle template. If your project already uses the External Dependency Manager for other SDKs, it keeps working. See [Android build setup](/sdk/unity/build-setup/android) and [iOS build setup](/sdk/unity/build-setup/ios) for what the package changes in the exported projects.

### 1.2 Requirements

7.x needs Unity 2021.3 or later, an iOS 15.0 or later deployment target (the package raises a lower one on export) and Android API 21 or later. See [Overview](/sdk/unity/overview#requirements).

### 1.3 Namespaces and the name clash

6.x code wrote `using BugseePlugin;` and then `Bugsee.Launch(...)`. In 7.x the namespace and the static class share the name `Bugsee`, so `Bugsee.Launch(...)` does not compile in code outside the namespace. Alias the class and import the other types by their namespaces:

```csharp
using Bugsee.Contracts.Options;   // options, enums such as IssueSeverity and LogLevel
using BugseeSdk = Bugsee.Bugsee;  // the static class
```

| Types | 7.x namespace |
| --- | --- |
| The `Bugsee` class | `Bugsee` |
| Launch options, `Options`, `OptionsBuilder`, `IssueSeverity`, `LogLevel`, `FrameRate`, `VideoMode`, `VideoQuality`, `ReportingUIStyle`, `CrashSignals`, `CrashHandlerType` | `Bugsee.Contracts.Options` |
| `IReport`, `IAttachment`, `IReportHandler`, `ReportHandlerBase` | `Bugsee.Contracts.Reporting` |
| `ILifecycleEventListener`, `LifecycleEvents`, `BugseeStatus`, `DeleteScope` | `Bugsee.Contracts.Lifecycle` |
| `IAppearance`, `ReportAppearance`, `FeedbackAppearance` | `Bugsee.Contracts.Appearance` |
| `IFeedback` | `Bugsee.Contracts.Feedback` |
| `INetworkEvent`, `ILogEvent`, `IBreadcrumb`, `EventFilter<T>` | `Bugsee.Contracts.Exchange` |
| `ISpan` | `Bugsee.Contracts.Apm` |

## 2. Launch

In 6.x the usual launch was the `BugseeLauncher` component: it held one token field per platform, chose the options with static handlers, and called `Bugsee.Launch` in `Awake` on mobile platforms. Launching from code looked like this.

```csharp
// 6.x. Namespace BugseePlugin, class Bugsee is a MonoBehaviour.
using BugseePlugin;
using UnityEngine;

public class MyLaunch : MonoBehaviour
{
    void Awake()
    {
        gameObject.AddComponent<Bugsee>();   // required for a manual launch

#if UNITY_ANDROID
        var options = new AndroidLaunchOptions
        {
            ShakeToTrigger = true,
            NotificationBarTrigger = true,
            MaxRecordingTime = 60,
        };
        Bugsee.Launch("<your Android app token>", options);
#elif UNITY_IOS
        var options = new IOSLaunchOptions { ShakeToReport = true };
        Bugsee.Launch("<your iOS app token>", options);
#endif
    }
}
```

The 7.x equivalent has no component and no `AddComponent`. The typed options convert to the `Dictionary<string, object>` that `Launch` takes.

```csharp
// 7.x
using Bugsee.Contracts.Options;
using UnityEngine;
using BugseeSdk = Bugsee.Bugsee;

public class MyLaunch : MonoBehaviour
{
    void Awake()
    {
#if UNITY_ANDROID
        var options = new AndroidLaunchOptions
        {
            ReportingTriggerByShake = true,
            ReportingTriggerByNotification = true,
            Duration = 60,
        };
        BugseeSdk.Launch("<your Android app token>", options);
#elif UNITY_IOS
        var options = new IOSLaunchOptions { ReportingTriggerByShake = true };
        BugseeSdk.Launch("<your iOS app token>", options);
#endif
    }
}
```

What changes in how you launch:

- **One token per platform stays.** App tokens are per platform in both versions.
- **`Launch` throws `ArgumentException` for an empty token.** It does not wait for the native SDK. For the result, use `LaunchAsync`, and read `Bugsee.IsLaunched` and `Bugsee.Status`. See [Lifecycle & status](/sdk/unity/lifecycle).
- **A call without options uses the native SDK defaults.** In 6.x, `Launch(token)` sent the wrapper's own defaults for every option (see section 4). In 7.x the typed properties are write-only and an option you do not set is not sent, so the native SDK applies its default.
- **You can read an option only through `GetLaunchOptions`.** The 6.x option properties had getters. The 7.x ones only have setters, so `options.MaxRecordingTime` style reads do not compile. After launch, `Bugsee.GetLaunchOptions()` returns the effective options.
- **`Relaunch(options)` replaces the whole option set.** Pass the full set again. There is also `RelaunchAsync`.
- **`Stop` takes an optional completion callback**, and there is `StopAsync`.
- **In the Unity Editor and on other platforms, `Launch` does nothing.** Test on a device.
- **The dictionary overload now uses `com.bugsee.option.*` keys.** The 6.x short keys (`Bugsee.ShakeToReportKey`, `MaxRecordingTimeKey` and the other constants, whose values were strings such as `"ShakeToReport"`) do not exist in 7.x, and the package does not translate them. Use the constants of the `Options` class, or the typed options. See [Configuration](/sdk/unity/configuration).
- **An endpoint for an on-premises server.** 6.x had the constant `Bugsee.EndpointKey` (`"endpoint"`). 7.x has no typed endpoint option. Set it with `options.SetCustomOption("com.bugsee.option.$$ENDPOINT", url)`, which works on both platforms.

## 3. API mapping

All 7.x members below are on the static class `Bugsee`, which the examples call as `BugseeSdk`.

### 3.1 Methods and events

| 6.x (`BugseePlugin.Bugsee`) | 7.x | Notes |
| --- | --- | --- |
| `Launch(string, BugseeLaunchOptions = null)` and `Launch(string, IDictionary<string, object>)` | `Launch(string, Dictionary<string, object> options = null)` | Typed options, `OptionsBuilder` and a dictionary all go to the same parameter. It is a `Dictionary<string, object>`, so pass another `IDictionary` as `new Dictionary<string, object>(d)`. |
| `Relaunch(BugseeLaunchOptions = null)` | `Relaunch(Dictionary<string, object> options = null)`, `RelaunchAsync` | |
| `Stop()` | `Stop(Action completion = null)`, `StopAsync` | |
| `ShowReport(summary, description, BugseeSeverityLevel severity = High)` | `ShowReportDialog(summary, description, IssueSeverity? severity = null, IList<string> labels = null)` | Renamed. `null` severity uses `ReportingDefaultBugPriority`. 6.x always sent High. |
| `Upload(summary, description, BugseeSeverityLevel severity = High)` | `Upload(summary, description, IssueSeverity? severity = null, IList<string> labels = null)` | Same severity change. |
| `Pause()`, `Resume()` | `StartBlackout()`, `EndBlackout()`, `IsBlackout` | `Pause` and `Resume` still exist in 7.x but are marked obsolete and call the blackout methods. |
| `Event(name, IDictionary<string, object> = null)` | `Event(name, IDictionary<string, object> = null)` | Unchanged. See [Custom events & traces](/sdk/unity/events-and-traces). |
| `Trace(name, object)` | `Trace(name, object)` | Unchanged signature. |
| `Log(message, BugseeLogLevel level = Debug)` | `Log(message, LogLevel level = Info)` | The default level is now `Info`. A second overload takes `requiresFiltering`. See [Console logs](/sdk/unity/logs). |
| `LogException(Exception)` | `LogException(Exception, IDictionary<string, object> options = null)` | Source compatible. `LogUnhandledException` is new. |
| `TestExceptionCrash()`, `TestSignalCrash()` | `TestCrash()` | One method. On Android it crashes the app with a Java exception, on iOS it triggers the SDK's test crash. |
| `ShowFeedbackUI()`, `SetFeedbackGreetingMessage(string)` | `Feedback.ShowFeedbackUi()`, `Feedback.SetDefaultGreeting(string)` | The feedback chat is an opt-in add-on. See [Feedback](/sdk/unity/feedback). |
| `SetAttribute(key, value)` returns `bool` | `SetAttribute(key, value)` returns nothing | Invalid keys and values throw `ArgumentException`. See [User & session data](/sdk/unity/user-session-data). |
| `GetAttribute(key)` | `GetAttribute(key)`, `GetAllAttributes()` | Values read back as `string`, `bool`, `long` or `double`. |
| `ClearAttribute(key)`, `ClearAllAttributes()` return `bool` | Same names, return nothing | |
| `SetEmail`, `GetEmail`, `ClearEmail` | `SetUserIdentifier`, `GetUserIdentifier`, `ClearUserIdentifier` | There is no email API in 7.x. An email address is a valid identifier. For one report, set `IReport.Email`. |
| `CaptureViewHierarchy()` | `CaptureViewHierarchy()` | Unchanged. See [View hierarchy](/sdk/unity/view-hierarchy). |
| `AddSecureRect(Rect)`, `RemoveSecureRect(Rect)` return `bool` on iOS and nothing on Android | `AddSecureRectangle(RectInt)`, `RemoveSecureRectangle(RectInt)`, and `AddSecureScreenRectangle(Rect, displayId)` | The first pair takes native pixels with a top-left origin. The screen variant takes Unity screen space. See [Privacy: Video](/sdk/unity/privacy/video). |
| `RemoveAllSecureRects()`, `GetAllSecureRects()` returns `Rect[]` | `RemoveAllSecureRectangles()`, `GetAllSecureRectangles()` returns `RectInt[]` | |
| `OnAttachmentForReport` event | `SetReportHandler(IReportHandler)` | See 3.3. |
| `OnLifecycleEvent` event | `LifecycleEvent` event, `SetLifecycleEventListener` | See 3.4. |
| `Appearance` (`IBugseeAppearance`) | `Appearance` (`IAppearance`) | See 3.5. |
| `Assert(condition, description)` | None | Removed. In 6.x it was a no-op on Android. |
| `GetDeviceID()` | None | Removed. |
| `Snapshot()` | None | Removed together with the 6.x `V4` video mode. |
| `OnRecordingStarted` event | None | Removed. |
| `OnHandleUnresolvedException(object, UnhandledExceptionEventArgs)` | None | The 7.x SDK installs its managed exception hooks itself. See section 5. |
| `ShakeToReportKey`, `MaxRecordingTimeKey` and the other key constants | `Options` constants | See section 2. |

### 3.2 Enums and types

| 6.x | 7.x | Notes |
| --- | --- | --- |
| `BugseeSeverityLevel`: `Low` 1, `Medium`, `High`, `Critical`, `Blocker` 5 | `IssueSeverity`: `VeryLow` 1, `Medium`, `High`, `Critical`, `Blocker` 5 | `Low` is now `VeryLow`. The numbers are the same. |
| `BugseeLogLevel`: `Invalid` 0, `Error` 1 to `Verbose` 5 | `LogLevel`: `Error` 1 to `Verbose` 5 | `Invalid` is gone. |
| `BugseeFrameRate`: `Low`, `Medium`, `High` | `FrameRate`: `Low`, `Medium`, `High`, `Raw` | `Raw` is new and is meaningful for `VideoMode.DirectBuffers` only. |
| `BugseeStyle`: `Default` 0, `Dark` 1, `BasedOnStatusBar` 2 | `ReportingUIStyle`: `Light` 0, `Dusk` 1, `BasedOnStatusBar` 2, `System` 3 | The default is now `System`. iOS only. |
| `BugseeAndroidVideoMode`: `None`, `V1`, `V2`, `V3`, `V4` | `VideoMode`: `None` 0, `V1` 1, `V2` 2, `Fullscreen` 20, `DirectBuffers` 21 | `V3` and `V4` no longer exist. The 6.x `V2` used MediaProjection and asked the user for consent; in 7.x that is `Fullscreen`. The 7.x `V2` is the Android SDK's default capture engine. See [Video capture](/sdk/unity/video-capture). |
| `BugseeLifecycleEventType` | Strings in `LifecycleEvents` | See 3.4. |
| `BugseeReport`, `BugseeAttachment` structs | `IReport`, `IAttachment` | See 3.3. |

### 3.3 Attachments and the report handler

6.x added attachments by returning a list from the `OnAttachmentForReport` event. In 7.x you register a report handler and call `AddAttachmentBytes` or `AddAttachmentFile` on the report from `OnAfterReportCreated`. Both return `null` when the report refuses the attachment. The handler must call the completion callback.

```csharp
// 6.x
Bugsee.OnAttachmentForReport += report => new List<BugseeAttachment>
{
    new BugseeAttachment { name = "state", filename = "state.json", data = stateBytes },
};
```

```csharp
// 7.x
using System;
using Bugsee.Contracts.Reporting;
using BugseeSdk = Bugsee.Bugsee;

public class StateAttachments : ReportHandlerBase
{
    readonly byte[] _stateBytes;

    public StateAttachments(byte[] stateBytes) { _stateBytes = stateBytes; }

    public override void OnAfterReportCreated(IReport report, bool isTerminating, Action completionCallback)
    {
        IAttachment attachment = report.AddAttachmentBytes(_stateBytes, "state", "application/json");
        if (attachment != null)
        {
            attachment.Filename = "state.json";
        }

        completionCallback?.Invoke();
    }
}

// Once, after launch or before it:
// BugseeSdk.SetReportHandler(new StateAttachments(bytes));
```

The handler also lets you change the summary, description, severity, labels and attributes of the report. See [Report handler](/sdk/unity/report-handler) and [Bug reporting](/sdk/unity/manual/bug-reporting).

### 3.4 Lifecycle events

6.x raised `OnLifecycleEvent` with a `BugseeLifecycleEventType` value. 7.x raises `LifecycleEvent` with an event name from `LifecycleEvents` and an optional payload, and you can instead register an `ILifecycleEventListener`.

```csharp
using Bugsee.Contracts.Lifecycle;
using BugseeSdk = Bugsee.Bugsee;

BugseeSdk.LifecycleEvent += (eventType, data) =>
{
    if (eventType == LifecycleEvents.RelaunchedAfterCrash)
    {
        UnityEngine.Debug.Log("The app was relaunched after a crash.");
    }
};
```

| 6.x `BugseeLifecycleEventType` | 7.x `LifecycleEvents` |
| --- | --- |
| `Launched` | `Launched` |
| `Stopped` | `Stopped` |
| `RelaunchedAfterCrash` | `RelaunchedAfterCrash` |
| `BeforeReportShown`, `AfterReportShown` | `BeforeReportShown`, `AfterReportShown` |
| `BeforeReportUploaded`, `AfterReportUploaded` | `BeforeReportUploaded`, `AfterReportUploaded` |
| `BeforeFeedbackShown`, `AfterFeedbackShown` | `BeforeFeedbackShown`, `AfterFeedbackShown` |
| `Paused`, `Resumed` | `BlackoutStarted`, `BlackoutEnded` |
| `Started` | No member of that name. See [Lifecycle & status](/sdk/unity/lifecycle#lifecycle-events). |

7.x adds `Launching`, `Stopping`, `BeforeReportAssembled`, `AfterReportAssembled`, `ReportAssemblyFailed`, `ReportUploadFailedWithFutureRetry` and `ReportUploadFailed`.

### 3.5 Appearance

6.x had typed properties: `Bugsee.Appearance.Report.BackgroundColor = ...`. 7.x has one string-keyed surface, `IAppearance`, with `SetColor`, `GetColor`, `SetString` and `GetString`, and the key constants `ReportAppearance` and `FeedbackAppearance`. See [Appearance](/sdk/unity/appearance).

```csharp
using Bugsee.Contracts.Appearance;
using UnityEngine;
using BugseeSdk = Bugsee.Bugsee;

BugseeSdk.Appearance
    .SetColor(ReportAppearance.BackgroundColor, new Color32(16, 24, 40, 255))
    .SetString(ReportAppearance.SummaryPlaceholder, "What went wrong?");
```

They are in [Configuration](/sdk/unity/configuration).

## 5. Behavior changes

### 5.1 Changed defaults

Several options start with another value than they did in 6.x. The table in 4.1 has the numbers. Check these first:

- **Shake-to-report is off.** On Android it was on in 6.x. If your game used shake to open the report dialog on Android, set `ReportingTriggerByShake = true`. On iOS the 6.x wrapper already started with shake off.
- **The Android notification-bar trigger is off.** Set `ReportingTriggerByNotification = true` on `AndroidLaunchOptions` to keep it.
- **The iOS screenshot trigger is off.** The 6.x iOS wrapper had it on. Set `ReportingTriggerByScreenshot = true` to keep it.
- **`MaxDataSize` is 150 MB, not 50.**
- **View hierarchy capture is on.** The 6.x wrapper had it off. It sends the 2D bounds of the nodes and a 3D `scene` block of cameras and boxes unless you set `CaptureSceneGraph` to `NamesOnly` or `None`: see [View hierarchy](/sdk/unity/view-hierarchy#how-much-of-the-scene-is-sent).
- **Exit detection is on.** Application exits (on Android, the reasons of `ApplicationExitInfo`; on iOS, out-of-memory kills) are reported unless you switch them off. On Android set `DetectAndReportExit = false`. On iOS call `options.SetCustomOption(Options.DetectAndReportExit, false)`.
- **Early-crash handling is on.** The 6.x iOS option `AppLaunchCrashDetection` was off.
- **The default bug severity on iOS is `High`.** It was `Low` in the 6.x options.
- **The Android video mode default is `V2`** (the SDK's default capture engine), where 6.x used `V3`.
- **`Log` defaults to `LogLevel.Info`.** The 6.x default was `Debug`.
- **Breadcrumbs are off.** `AddBreadcrumb` records nothing until you set `CaptureBreadcrumbs = true`. See [Breadcrumbs](/sdk/unity/breadcrumbs).

The native SDKs changed other defaults between their 6.x and 7.x lines. They are in the native guides: [Android](/sdk/android/migration) and [iOS](/sdk/ios/migration).

### 5.2 Managed exceptions are a separate switch

In 6.x, the `AppDomain.UnhandledException` and Unity log hooks for managed exceptions were installed only when `CrashReport` was `true`. In 7.x they follow `CaptureManagedExceptions` (default `true`), which is independent of `DetectAndReportCrash`. To stop reporting C# exceptions, set `CaptureManagedExceptions = false`. `CaptureUnobservedTaskExceptions` (default `true`) controls the unobserved task exceptions. See [Crash & error reporting](/sdk/unity/manual/crash-error-reporting).

The client signature of a managed exception changed too. 6.x hashed the exception name, every raw stack line and the build GUID. 7.x uses the short type name and the first user frames, and leaves out the message, the build GUID, IL offsets and directories. Existing issues can regroup after you update.

### 5.3 Severity

`ShowReportDialog` and `Upload` take `IssueSeverity?`. Pass `null` or omit it to use `ReportingDefaultBugPriority`, which is `High` unless you configure it. In 6.x both calls always sent `High` and ignored the default. `IReport.Severity` is `IssueSeverity?` as well: `null` is unset.

### 5.4 Attribute values

`GetAttribute`, `GetAllAttributes` and `IReport.GetAttribute` return `long` for every integer and `double` for floating-point values, on both platforms. On 6.x Android, `GetAttribute` returned `int` when the value fit and `float` for decimals, so code that unboxes with `(int)` or `(float)` throws `InvalidCastException` in 7.x. Use `Convert.ToInt32` or cast to `long`. On 6.x iOS the call returned a string.

### 5.5 Deleting collected data

`DeleteCollectedDataOnDevice` is new in 7.x. On Android the plain call also deletes finished reports that were not uploaded yet, and stops the SDK first. To keep reports that wait for upload, call `DeleteCollectedDataOnDevice(DeleteScope.CaptureAndIntermediate)`. See [Lifecycle & status](/sdk/unity/lifecycle#delete-collected-data).

### 5.6 Native crash signals

`CrashSignals` is a shared launch option in 7.x and reaches both platforms. On Android it is read by the NDK module. A mask meant only for iOS, for example `CrashSignals.None`, also narrows native signal capture on Android. Leave it out of the Android options, or set it per platform. See [Configuration](/sdk/unity/configuration#crashsignals).

## 6. Build and CI changes

- **No `.unitypackage`, no native binaries in the project.** The Android SDK (Gradle) and the iOS SDK (Swift Package Manager) are added to the generated projects by the package.
- **Symbol upload is part of the build and opt-in.** Set `BUGSEE_APP_TOKEN` to turn it on and `BUGSEE_NO_SYMBOL_UPLOAD` to turn all uploads off. A missing token or tool is a warning, never a failed build. See [Symbolication](/sdk/unity/symbolication/overview) and [Build environment variables](/sdk/unity/symbolication/environment-variables).
- **If your CI sets `BUGSEE_BUILD_UUID`,** read its entry in the variable list. The Android mapping upload is keyed by the build id the built app carries, and the variable applies only when the app has none and the value is a UUID.
- **An iOS export on Xcode 27 or later can add a `BugseeCrashReport` extension target** with an App Group entitlement on your app. By default it is added only in an interactive Editor build with Automatically Sign on and a team, never in batch mode. Set `BUGSEE_IOS_CRASH_EXTENSION=0` to keep the export as it was. See [Crash Report Extension](/sdk/unity/issue-detection/crash-report-extension).

## 7. What is new in 7.x

- **Lifecycle:** `LaunchAsync`, `RelaunchAsync`, `StopAsync`, `IsLaunched`, `Status`, `DeleteCollectedDataOnDeviceAsync`. See [Lifecycle & status](/sdk/unity/lifecycle).
- **Reports:** `CreateReport`, `Upload(IReport)`, `Discard`, and the report handler. See [Bug reporting](/sdk/unity/manual/bug-reporting).
- **Events and context:** `AddBreadcrumb`, `SetUserIdentifier`, `GetAllAttributes`, and filters for logs, network events and breadcrumbs. See [Breadcrumbs](/sdk/unity/breadcrumbs), [Network events](/sdk/unity/network) and [Privacy overview](/sdk/unity/privacy/overview).
- **Notification relay:** `Notify`. See [Notification relay](/sdk/unity/notification-relay).
- **Performance monitoring:** `StartTransaction` and spans. See [Performance monitoring](/sdk/unity/performance).
- **Privacy:** screen-space secure rectangles, secure web views (Android and iOS), and `ApplyDefaultNetworkSanitizer`. See [Privacy: Video](/sdk/unity/privacy/video) and [Privacy: Network](/sdk/unity/privacy/network).
- **Detection:** hangs, exits, HTTP errors, anomalies and frustration, plus the iOS Crash Report Extension and the opt-in iOS native early launch. See [Issue detection](/sdk/unity/issue-detection/overview).
- **Symbolication:** Editor and Xcode uploads of native symbols, mappings and the IL2CPP line map. See [Symbolication](/sdk/unity/symbolication/overview).

- [ ] Port the launch to `BugseeSdk.Launch(token, options)` with `AndroidLaunchOptions` or `IOSLaunchOptions`.
- [ ] Rename options (4.1), remove the dropped ones (4.2), and set the trigger options you relied on (shake, notification bar, iOS screenshot).
- [ ] Rename `ShowReport` to `ShowReportDialog`, `BugseeSeverityLevel` to `IssueSeverity`, `BugseeLogLevel` to `LogLevel`.
