Events mark moments in the app's life ("payment processed"); traces follow how a value changes
("credit balance"). Both appear on the report's timeline next to the video, logs and network
traffic.

## Custom events

An event has a name and an optional dictionary of parameters.

<Tabs groupId="lang-ios">
  <TabItem value="objective-c" label="Objective-C">

```objectivec
// Without parameters
[Bugsee event:@"payment_processed"];

// With parameters
[Bugsee event:@"payment_processed"
       params:@{@"amount": @125,
                @"currency": @"USD"}];
```

  </TabItem>
  <TabItem value="swift" label="Swift">

```swift
// Without parameters
Bugsee.event("payment_processed")

// With parameters
Bugsee.event("payment_processed", params: ["amount": 125, "currency": "USD"])
```

  </TabItem>
</Tabs>

An event with an empty name is ignored. In 6.x this was `registerEvent:` /
`registerEvent:withParams:`.

## Custom traces

A trace is a named value. Set it every time the value changes; the report shows how it changed
over the recorded period.

<Tabs groupId="lang-ios">
  <TabItem value="objective-c" label="Objective-C">

```objectivec
[Bugsee trace:@"credit_balance" value:@15];
```

  </TabItem>
  <TabItem value="swift" label="Swift">

```swift
Bugsee.trace("credit_balance", value: 15)
```

  </TabItem>
</Tabs>

Bugsee remembers the last value of each trace, so a report shows the value a trace had when its
recording starts even if it was set long before. A trace with an empty name is ignored. In 6.x this
was `traceKey:withValue:` (Swift `trace(key:value:)`).

Events and traces are recorded once the SDK status is `Launched`. Those sent earlier — while the
SDK is stopped, while a launch [waits for the app to become active](/sdk/ios/lifecycle/#when-the-launch-waits-for-the-app-to-become-active), or while it is still `Launching` — may be lost.

## View hierarchy

Bugsee captures the view hierarchy of the screen with each bug and error report, so you can inspect
the views behind the screenshot. It is controlled by `BugseeOptionCaptureViewHierarchy`
(`viewHierarchyEnabled`, default `YES`).

To record the hierarchy at a moment of your choosing — before a transition you want to inspect,
say — call `captureViewHierarchy`. The snapshot goes into the recording, so a report whose recorded
period covers that moment includes it.

<Tabs groupId="lang-ios">
  <TabItem value="objective-c" label="Objective-C">

```objectivec
[Bugsee captureViewHierarchy];
```

  </TabItem>
  <TabItem value="swift" label="Swift">

```swift
Bugsee.captureViewHierarchy()
```

  </TabItem>
</Tabs>

- `captureViewHierarchy` does nothing while `BugseeOptionCaptureViewHierarchy` is `NO`, or while
  the SDK is not fully running (`BugseeStatusLaunched`).
- No view hierarchy is captured during a [blackout](/sdk/ios/privacy/video), automatically or by
  this call.
- Each snapshot adds to the size of the report, more so for deep hierarchies.

## System traces

Besides your own traces, every report carries traces that the SDK records on its own while it
runs. They need no code.

| Recorded by default | What it shows |
| --- | --- |
| CPU | The app's CPU usage. |
| Memory | The app's resident, virtual and footprint memory, the memory still available to it, the device's total memory, and whether the system reports memory pressure. |
| Queue latency | Latency of the main queue and of the high, default, low and background global queues. |
| Power and thermal | Battery level and charging state, Low Power Mode, and the thermal state. |
| Network | Network reachability. |
| Cellular | For each SIM: the radio technology and whether it has a data connection. Bugsee does not link CoreTelephony; unless your app loads it, the trace reports cellular as unavailable. The carrier name, MCC and MNC are recorded only with `BugseeOptionCaptureDeviceAndNetworkNames`. Not on tvOS or visionOS. |
| App and screen | Foreground or background, the current view controller, orientation and screen brightness (not on tvOS or visionOS), the connected displays, and the frame rate. |
| Accessibility | Whether VoiceOver or Switch Control is running. |
| NFC | Whether the device can read NFC tags. Recorded only if your app links CoreNFC. |
| Capture | Whether recording is active or in a blackout. With `BugseeOptionCaptureDiskSpace` on, also the low and no disk space states; see [Disk space](/sdk/ios/configuration#disk-space). |
| Fold state | Fold state and hinge angle, on devices that report them. Not on tvOS or visionOS. |

These are recorded only when you turn on their option:

| Trace | Option | Notes |
| --- | --- | --- |
| Disk space | `BugseeOptionCaptureDiskSpace` | Free and total disk space. See [Disk space](/sdk/ios/configuration#disk-space). |
| Bluetooth | `BugseeOptionCaptureBluetoothStatus` | Bluetooth state. Your `Info.plist` must contain `NSBluetoothAlwaysUsageDescription`, and the app must already have Bluetooth permission: Bugsee never asks for it. Without the permission, the trace records the state as unknown or unauthorized. |
| Wi-Fi | `BugseeOptionCaptureDeviceAndNetworkNames` | The Wi-Fi network name (SSID) and BSSID. iOS returns them only to an app with the Wi-Fi information entitlement (and, from iOS 13, location permission). Not on tvOS or visionOS. |
