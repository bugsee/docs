You configure Bugsee with the options you pass to `launchWithToken:` (and later to `relaunch`). An option you leave out takes its default, listed in the tables below.

## Launching with options

Options are passed in one of two forms. Both have the same effect.

**A `BugseeOptions` object.** Start from `defaultOptions` (Swift `BugseeOptions.default()`), set its properties, and launch with it. Options that have no property are set by key with `updateLaunchOptions:` (Swift `updateLaunch(_:)`).

<Tabs groupId="lang-ios">
  <TabItem value="objective-c" label="Objective-C">

```objectivec
BugseeOptions *options = [BugseeOptions defaultOptions];
options.maxRecordingTime = 60;
options.shakeToReport = YES;
options.screenshotToReport = NO;

// Options that have no BugseeOptions property are set by key:
[options updateLaunchOptions:@{
    BugseeOptionDetectAndReportHang : @YES,
    BugseeOptionCaptureBreadcrumbs  : @YES,
}];

[Bugsee launchWithToken:@"<your_app_token>" options:options];
```

  </TabItem>
  <TabItem value="swift" label="Swift">

```swift
let options = BugseeOptions.default()
options.maxRecordingTime = 60
options.shakeToReport = true
options.screenshotToReport = false

// Options that have no BugseeOptions property are set by key:
options.updateLaunch([
    BugseeOptionDetectAndReportHang: true,
    BugseeOptionCaptureBreadcrumbs: true,
])

Bugsee.launch(token: "<your_app_token>", options: options)
```

  </TabItem>
</Tabs>

**A dictionary** of `BugseeOption*` keys. In Swift, this overload is `launch(token:dictionaryOptions:)`.

<Tabs groupId="lang-ios">
  <TabItem value="objective-c" label="Objective-C">

```objectivec
NSDictionary *options = @{
    BugseeOptionConfigDuration               : @60,
    BugseeOptionReportingTriggerByShake      : @YES,
    BugseeOptionReportingTriggerByScreenshot : @NO,
    BugseeOptionDetectAndReportCrash         : @YES,
};

[Bugsee launchWithToken:@"<your_app_token>" andOptions:options];
```

  </TabItem>
  <TabItem value="swift" label="Swift">

```swift
let options: [String: Any] = [
    BugseeOptionConfigDuration: 60,
    BugseeOptionReportingTriggerByShake: true,
    BugseeOptionReportingTriggerByScreenshot: false,
    BugseeOptionDetectAndReportCrash: true,
]

Bugsee.launch(token: "<your_app_token>", dictionaryOptions: options)
```

  </TabItem>
</Tabs>

Enum-typed options take an `NSNumber` in a dictionary, for example `@(BugseeCrashHandlerTypeBSD)` in Objective-C or `BugseeCrashHandlerType.bsd.rawValue` in Swift.

### Option keys

Each `BugseeOption*` constant holds a `com.bugsee.option.*` string, the same key the Android SDK and the cross-platform SDKs use. Always pass the constants rather than typing the strings.

The 6.x key constants, such as `BugseeShakeToReportKey` or `BugseeMaxRecordingTimeKey`, still compile: in 7.x they hold the new `com.bugsee.option.*` strings. A dictionary that carries the 6.x strings themselves, for example `@"ShakeToReport"` saved by an older build, is translated to the new keys too. Prefer the `BugseeOption*` constants in new code: they are the names this page documents, and options added in 7.x have no 6.x name. A few 6.x options were removed in 7.x; see [Migrating from 6.x to 7.x](/sdk/ios/migration).

The launch `started:` block and the SDK status are covered in [Lifecycle & status](/sdk/ios/lifecycle/).

## Stopping

Stopping ends recording and releases the resources the SDK uses. The completion block runs once the SDK has stopped.

<Tabs groupId="lang-ios">
  <TabItem value="objective-c" label="Objective-C">

```objectivec
[Bugsee stop:^{
    // Bugsee is stopped
}];
```

  </TabItem>
  <TabItem value="swift" label="Swift">

```swift
Bugsee.stop {
    // Bugsee is stopped
}
```

  </TabItem>
</Tabs>

A launch called while the SDK is stopping is refused. To launch again with new options, call `launchWithToken:` from the stop completion, or use `relaunch`. Stopping also ends an active [blackout](/sdk/ios/privacy/video/).

## Relaunching

Relaunching stops the running SDK and launches it again with new options and the same app token.

<Tabs groupId="lang-ios">
  <TabItem value="objective-c" label="Objective-C">

```objectivec
// With a BugseeOptions object
[Bugsee relaunchWithOptions:options];

// With a dictionary
[Bugsee relaunchWithDictionaryOptions:@{ BugseeOptionCaptureVideo : @NO }];

// Told whether the relaunch went ahead
[Bugsee relaunchWithOptions:options started:^(BOOL success) {
    NSLog(@"Relaunched: %d", success);
}];

// The current app token and the default options
[Bugsee relaunch];
```

  </TabItem>
  <TabItem value="swift" label="Swift">

```swift
// With a BugseeOptions object
Bugsee.relaunch(options: options)

// With a dictionary
Bugsee.relaunch(dictionaryOptions: [BugseeOptionCaptureVideo: false])

// Told whether the relaunch went ahead
Bugsee.relaunch(options: options) { success in
    print("Relaunched: \(success)")
}

// The current app token and the default options
Bugsee.relaunch()
```

  </TabItem>
</Tabs>

A relaunch goes ahead only while the SDK is running (`status` is `BugseeStatusLaunched`). While it is stopped, launching or stopping, the relaunch is refused and `started:` receives `NO`. A relaunch called while another one is in progress joins it, and its own options are not applied. An active blackout stays on across a relaunch.

## Reading the options in effect

`getLaunchOptions` returns the options the SDK applies: the ones the app passed, merged over the defaults, keyed by the `com.bugsee.option.*` strings. Before the first launch it holds the defaults. `getHostLaunchOptions` returns only the options the app itself passed, so you can tell "the app asked for this" from "this is the default".

<Tabs groupId="lang-ios">
  <TabItem value="objective-c" label="Objective-C">

```objectivec
NSDictionary<NSString *, id> *effective = [Bugsee getLaunchOptions];
NSNumber *duration = effective[BugseeOptionConfigDuration];

NSDictionary<NSString *, id> *passed = [Bugsee getHostLaunchOptions];
```

  </TabItem>
  <TabItem value="swift" label="Swift">

```swift
let effective = Bugsee.getLaunchOptions()
let duration = effective[BugseeOptionConfigDuration] as? Int

let passed = Bugsee.getHostLaunchOptions()
```

  </TabItem>
</Tabs>

`getHostLaunchOptions` holds only values the SDK accepted. After `stop:` it still describes the last configuration, and the next launch or relaunch replaces it.

## Crash handler

Two options control how crashes are intercepted. They are covered in detail in [Crashes](/sdk/ios/issue-detection/crashes/).

`crashHandlerType` (`BugseeOptionCaptureCrashHandlerType`) takes a `BugseeCrashHandlerType`:

| Value | Swift | What Bugsee installs |
| --- | --- | --- |
| `BugseeCrashHandlerTypeMachAndBSD` | `.machAndBSD` | A Mach exception handler and BSD signal handlers, so both hardware faults and signals raised by software (`raise()`, `kill()`) are reported. The default. |
| `BugseeCrashHandlerTypeMach` | `.mach` | A Mach exception handler, plus a BSD signal handler for `SIGABRT`. Other signals raised by software are not reported. |
| `BugseeCrashHandlerTypeBSD` | `.bsd` | BSD signal handlers only. |

tvOS has no Mach exceptions, so every value works as `BugseeCrashHandlerTypeBSD` there.

`crashSignals` (`BugseeOptionCaptureCrashSignals`) takes a combination of `BugseeCrashSignals` values: `BugseeCrashSignalABRT`, `SEGV`, `BUS`, `ILL`, `FPE` and `TRAP` (Swift `.abrt`, `.segv`, `.bus`, `.ill`, `.fpe`, `.trap`), or `BugseeCrashSignalsAll`. The default, `BugseeCrashSignalsDefault`, intercepts every signal (the Xamarin and .NET SDKs leave out `SIGSEGV` and `SIGBUS`, which the .NET runtime handles itself); it works only on its own, not combined with other values. Leaving out `SIGABRT` also stops uncaught Objective-C exceptions from being reported.

<Tabs groupId="lang-ios">
  <TabItem value="objective-c" label="Objective-C">

```objectivec
BugseeOptions *options = [BugseeOptions defaultOptions];
options.crashHandlerType = BugseeCrashHandlerTypeMachAndBSD;
options.crashSignals = BugseeCrashSignalABRT | BugseeCrashSignalILL | BugseeCrashSignalTRAP;

[Bugsee launchWithToken:@"<your_app_token>" options:options];
```

  </TabItem>
  <TabItem value="swift" label="Swift">

```swift
let options = BugseeOptions.default()
options.crashHandlerType = .machAndBSD
options.crashSignals = [.abrt, .ill, .trap]

Bugsee.launch(token: "<your_app_token>", options: options)
```

  </TabItem>
</Tabs>

## Device and network names

With `BugseeOptionCaptureDeviceAndNetworkNames` off (the default), the device name, the Wi-Fi network name and the carrier name in the report's device information are recorded as `<redacted>`.

To read the Wi-Fi network name, the app must meet one of these requirements (see [Apple's documentation](https://developer.apple.com/documentation/systemconfiguration/cncopycurrentnetworkinfo)):

- The app uses Core Location and has the user's authorization to use location information.
- The app uses the `NEHotspotConfiguration` API to configure the current Wi-Fi network.
- The app has active VPN configurations installed.
- The app has an active `NEDNSSettingsManager` configuration installed.

Requesting location access needs two `Info.plist` keys with descriptions: "Privacy - Location Always and When In Use Usage Description" and "Privacy - Location When In Use Usage Description". The app must also have the **Access WiFi Information** capability in Xcode.

The carrier name comes from CoreTelephony, which Bugsee does not link itself: it is recorded only when your app loads that framework. From iOS 16 the system no longer provides it, and it is recorded as `<unavailable>`.

## Disk space

Bugsee reads free disk space with the API reason `E174.1`, which does not allow the information to leave the device. So unless `BugseeOptionCaptureDiskSpace` is on, nothing derived from free disk space goes into reports: the free and total disk space device properties and system traces, the low and no disk space states of the capture trace, and the disk-space lines of the internal log. Bugsee still watches free space to stop writing on a full disk; that never leaves the device. Turn this option on only in debug or development builds.
