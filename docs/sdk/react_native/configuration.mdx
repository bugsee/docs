You configure the SDK with the options you pass to `Bugsee.launch` (and later `Bugsee.relaunch`). The same `com.bugsee.option.*` keys work on both platforms, so there is no per-platform key mapping: apart from the endpoint the Expo plugin can supply, the options you pass are the options the SDK applies, on both platforms. Enum-typed options take numbers; see [Enum reference](#enum-reference).

## Two ways to pass options

`launch` and `relaunch` accept either form, and both have the same effect:

- **The options object**, from `createDefaultLaunchOptions()`, with typed accessors. Pass it as is; there is no serialize step to call.
- **A plain map** of `com.bugsee.option.*` keys, for options you build or merge yourself.

<Tabs groupId="options-form">

```ts
import Bugsee, { createDefaultLaunchOptions, LogLevel } from '@bugsee/react-native';

const options = createDefaultLaunchOptions();
options.duration = 120;
options.captureLogsLevel = LogLevel.Info;
options.wifiOnlyUpload = true;

Bugsee.launch(token, options);
```

  <TabItem value="map" label="Plain map">

```ts
import Bugsee, { LogLevel } from '@bugsee/react-native';

Bugsee.launch(token, {
  'com.bugsee.option.config.duration': 120,
  'com.bugsee.option.capture.logs.level': LogLevel.Info,
  'com.bugsee.option.config.wifi-only-upload': true,
});
```

`BugseeLaunchOptions.serialize(options)` returns the plain map an options object stands for, as a snapshot: a later change to the object does not change a map you already took.

## The options object

`createDefaultLaunchOptions()` returns an empty options object for the running platform: an `IOSLaunchOptions` on iOS, an `AndroidLaunchOptions` on Android. Pass a platform (`'ios'` or `'android'`) to get the other one; any other platform throws.

The object is **not** pre-filled with defaults. An option you leave unset is not sent at all, so the native SDK applies its own default. Setting an accessor to `undefined` removes the key again, rather than sending an empty value that would override the default.

Accessors shared by both platforms live on the base class, `BugseeLaunchOptions`. Platform-only accessors live on `AndroidLaunchOptions` and `IOSLaunchOptions`, so an iOS-only option cannot be set on an Android options object by accident. To reach one, narrow the object first:

```ts
import {
  AndroidLaunchOptions,
  IOSLaunchOptions,
  createDefaultLaunchOptions,
} from '@bugsee/react-native';

const options = createDefaultLaunchOptions();
if (options instanceof AndroidLaunchOptions) {
  options.triggerByNotification = false;
} else if (options instanceof IOSLaunchOptions) {
  options.captureDiskSpace = true;
}
```

### Any key: `setCustomOption`

`setCustomOption(key, value)` sets any option by its real `com.bugsee.option.*` key, whether or not it has an accessor. A custom key and an accessor write to the same map, so an option that has no accessor yet, including one added in a later 7.x native release, is reachable without a new release of this package. `undefined` removes the key, as with an accessor.

```ts
options.setCustomOption('com.bugsee.option.detect.http-errors', true);
options.setCustomOption('com.bugsee.option.capture.network.body-size-limit', 10240);
```

## Shared accessors

These accessors exist on both platforms.

| Accessor | Key | Type | Default | Description |
| --- | --- | --- | --- | --- |
| `duration` | `com.bugsee.option.config.duration` | number (seconds) | `60` | Length of the rolling capture buffer (video, logs, breadcrumbs). |
| `wifiOnlyUpload` | `com.bugsee.option.config.wifi-only-upload` | boolean | `false` | Defer report uploads until the device is on Wi-Fi. |
| `maxDataSize` | `com.bugsee.option.config.max-data-size` | number (MB) | `150` (Android) / `50` (iOS) | Disk space that reports waiting to be sent may take. Enforced on Android. On iOS this beta accepts the key but does not enforce it. See [Automatic retention](/sdk/react_native/privacy/cleanup#automatic-retention). |
| `captureVideo` | `com.bugsee.option.capture.video` | boolean | `true` | Record the screen for reports. |
| `captureNetwork` | `com.bugsee.option.capture.network` | boolean | `true` | Record network requests and responses. |
| `captureLogs` | `com.bugsee.option.capture.logs` | boolean | `true` | Capture logs automatically, including `console.*` output. `false` stops console forwarding; lines you send with `Bugsee.log` are still recorded. |
| `captureLogsLevel` | `com.bugsee.option.capture.logs.level` | `LogLevel` | `Verbose` | The most verbose level captured; less severe lines are dropped. `LogLevel.Info` keeps `Error`, `Warning` and `Info`. |
| `captureBreadcrumbs` | `com.bugsee.option.capture.breadcrumbs` | boolean | `false` | Record breadcrumbs. While off, `Bugsee.addBreadcrumb` records nothing, on both platforms. |
| `detectAndReportCrash` | `com.bugsee.option.detect.crash` | boolean | `true` | Report crashes. `false` also turns off the reporting of uncaught JavaScript errors, unhandled promise rejections and uncaught render errors. See [Turning automatic reporting off](/sdk/react_native/manual/crash-error-reporting#turning-automatic-reporting-off). |
| `detectAndReportHang` | `com.bugsee.option.detect.hang` | boolean | `false` | Report when the main thread is blocked long enough to count as a hang. |

The **Default** column applies to both platforms unless the row gives one per platform. Read the values in effect with [`getLaunchOptions()`](#reading-the-effective-options).

## Enum reference

Enum-typed options take a number. Use the exported constants rather than writing numbers: the values are each enum's internal value in the native SDKs, not its position in the list, so `LogLevel.Error` is `1` and `VideoMode.Fullscreen` is `20`.

```ts
import { FrameRate, IssueSeverity, VideoQuality } from '@bugsee/react-native';

options.setCustomOption('com.bugsee.option.capture.video.frame-rate', FrameRate.Medium);
options.setCustomOption('com.bugsee.option.capture.video.quality', VideoQuality.High);
options.setCustomOption('com.bugsee.option.reporting.defaults.bug-priority', IssueSeverity.Critical);
```

| Enum | Values | Used by |
| --- | --- | --- |
| `LogLevel` | `Error` 1, `Warning` 2, `Info` 3, `Debug` 4, `Verbose` 5 | `captureLogsLevel`, `Bugsee.log` |
| `VideoMode` | `None` 0, `V1` 1, `V2` 2, `Fullscreen` 20, `DirectBuffers` 21 | `videoMode` (Android) |
| `VideoQuality` | `Default` 0, `Medium` 1, `High` 2 | `capture.video.quality` |
| `FrameRate` | `Low` 1, `Medium` 2, `High` 3 | `capture.video.frame-rate` |
| `IssueSeverity` | `VeryLow` 1, `Medium` 2, `High` 3, `Critical` 4, `Blocker` 5 | `reporting.defaults.*-priority`, report severities |
| `CrashHandlerType` | `BSD` 1, `Mach` 2, `MachAndBSD` 3 | `crashHandlerType` (iOS) |

- `FrameRate` has no `Raw`: only Android has that rate, and the same number would mean different capture rates on the two platforms.
- `CrashHandlerType` is iOS only. `BSD` uses BSD signal handlers. `Mach` uses a Mach exception handler plus a BSD handler for `SIGABRT`; other signals raised by software (`raise()`, `kill()`) are not reported. `MachAndBSD`, the default, uses both, so hardware faults and signals raised by software are reported.

A number that names no value of the enum is handled differently on each platform. Android: it is dropped (as is a number that is not whole), so the option keeps its default. iOS: it is not checked, and is applied as given. Use the exported constants.

## Value types

Option values are booleans, numbers and strings. Other values are dropped without an error. Android: any value that is not one of those three types (an array, an object or `null`). iOS: a value whose type does not fit its key (a string for a boolean key, say). The option then keeps its default.

## Endpoint

The endpoint override is the one option whose key differs per platform, which is why `endpoint` is an accessor on `AndroidLaunchOptions` and `IOSLaunchOptions` rather than on the base class. Set it on the object returned by `createDefaultLaunchOptions()` and the right key is written:

```ts
const options = createDefaultLaunchOptions();
options.endpoint = 'https://bugsee.example.com';
```

| Platform | Key | What is sent |
| --- | --- | --- |
| Android | `com.bugsee.option.$$ENDPOINT` | The value, trimmed. Accepted with or without `/v2`. |
| iOS | `endpoint` | The value, trimmed, without trailing slashes, with `/v2` added unless it already ends in `/v2`. |

The `endpoint` getter returns what will be sent, so on iOS it reads back with `/v2`. An empty or blank value removes the override.

For a plain map, `endpointFor(platform, endpoint)` returns the entry to merge in, or `{}` for an empty value:

```ts
import { Platform } from 'react-native';
import Bugsee, { endpointFor } from '@bugsee/react-native';

Bugsee.launch(token, {
  'com.bugsee.option.config.duration': 60,
  ...endpointFor(Platform.OS === 'ios' ? 'ios' : 'android', 'https://bugsee.example.com'),
});
```

An Expo app can set the endpoint once in the [config plugin](/sdk/react_native/expo#custom-endpoint) instead. `launch` and `relaunch` then use it whenever their options carry no endpoint; an endpoint you pass yourself wins.

## Reading the effective options

`Bugsee.getLaunchOptions()` resolves to the options the native SDK reports as in effect, as a plain `com.bugsee.option.*` map, including the SDK's defaults for what you did not set:

```ts
async function logDuration() {
  const effective = await Bugsee.getLaunchOptions();
  console.log(effective['com.bugsee.option.config.duration']);
}
```

Both platforms answer before launch too, with the defaults.

An options object's getters return what you set on it, and nothing else, until you load the reported options into it. `BugseeLaunchOptions.refreshFrom(options, reported)` installs them; each call replaces the previous report. Getters then answer with the value you set, or failing that the reported one. Reported values are never sent back when the object is passed to `launch` or `relaunch`.

```ts
import Bugsee, { BugseeLaunchOptions, createDefaultLaunchOptions } from '@bugsee/react-native';

async function effectiveDuration() {
  const options = createDefaultLaunchOptions();
  BugseeLaunchOptions.refreshFrom(options, await Bugsee.getLaunchOptions());
  return options.duration; // the duration in effect
}
```

## Changing options at runtime

Options apply when the SDK launches. To change them later, pass a new set to `Bugsee.relaunch(options)`, which restarts the session; see [Lifecycle & status](/sdk/react_native/lifecycle).

## Worked example

```ts
import { Platform } from 'react-native';
import Bugsee, {
  AndroidLaunchOptions,
  CrashHandlerType,
  IOSLaunchOptions,
  IssueSeverity,
  LogLevel,
  createDefaultLaunchOptions,
} from '@bugsee/react-native';

const options = createDefaultLaunchOptions();
options.duration = 90;
options.captureBreadcrumbs = true;
options.captureLogsLevel = LogLevel.Info;
options.detectAndReportHang = true;
options.setCustomOption('com.bugsee.option.reporting.triggers.shake', false);
options.setCustomOption('com.bugsee.option.reporting.defaults.bug-priority', IssueSeverity.Medium);

if (options instanceof AndroidLaunchOptions) {
  options.triggerByNotification = false;
} else if (options instanceof IOSLaunchOptions) {
  options.crashHandlerType = CrashHandlerType.MachAndBSD;
}

Bugsee.launch(
  Platform.OS === 'ios' ? '<your iOS app token>' : '<your Android app token>',
  options,
);
```
